## Cel

Podnieść Seedvale z `three@0.180.x` do `three@0.185.x`, jednocześnie przechodząc przez wszystkie istotne zmiany z oficjalnego Migration Guide dla r180→r185. Nie traktować upgrade'u jako samej zmiany wersji: najpierw zidentyfikować używane API, nanieść wymagane migracje/deprecations, a następnie wykonać techniczną i wizualną regresję.

Źródła:

- [Three.js Migration Guide](https://github.com/mrdoob/three.js/wiki/Migration-Guide)
- [Three.js releases](https://github.com/mrdoob/three.js/releases)
- [Three.js r185 release](https://github.com/mrdoob/three.js/releases/tag/r185)

> Oficjalny Migration Guide zaleca przy dużych aktualizacjach inkrementację o 10 wersji, ponieważ ostrzeżenia deprecacyjne utrzymują się przez 10 wydań. Ten plan świadomie obejmuje tylko r180→r185, więc przed zmianami należy przejrzeć wszystkie pięć przejść wersji. [Migration Guide](https://github.com/mrdoob/three.js/wiki/Migration-Guide)

## Zmiany z Migration Guide do sprawdzenia

### r180 → r181 — rendering / PBR

> “The way indirect specular light for PBR materials is computed has been improved.”

> “rough materials tend to be a bit brighter than in previous versions.”

> “PMREM reflections have been improved.”

To jest **najważniejsza wizualnie zmiana dla Seedvale**. Sprawdzić szczególnie trawę, terrain, foliage, materiały o wysokim roughness, wodę, skały, drewno i wszystkie sceny z environment/PMREM. Jest to również istotne w kontekście wcześniejszego problemu z okresową zmianą jasności trawy, ale upgrade nie powinien być traktowany jako jego fix.

### r181 → r182 — shadows / WebGL

> “`PCFSoftShadowMap` with `WebGLRenderer` is now deprecated. Use `PCFShadowMap` which is now soft as well.”

Sprawdzić wszystkie ustawienia `shadowMap.type` i usunąć użycie `PCFSoftShadowMap`, jeżeli występuje.

### r182 → r183 — Clock i rendering

> “`Clock` has been deprecated. Please use `Timer` instead.”

Znaleźć wszystkie użycia `THREE.Clock` / importów `Clock` i przejść na `Timer`, jeżeli Seedvale faktycznie ich używa. Nie migrować mechanicznie własnych timerów symulacji — chodzi wyłącznie o API Three.js.

Dodatkowo zweryfikować:

- shadow bias, jeżeli używany jest WebGPURenderer — Seedvale korzysta z WebGL2, więc nie zakładać wpływu bez sprawdzenia;
- `RoomEnvironment`, jeżeli występuje;
- `Sky` / `SkyMesh`, jeżeli występuje;
- `PostProcessing` / `RenderPipeline`, `SSRNode`, `MeshPostProcessingMaterial` i `WebGLCubeRenderTarget` tylko jeśli są używane w kodzie.

### r183 → r184 — environment / mobile / WebGL2

> “The background and environment map rotation has been aligned to how 3D objects are rotated.”

> “`FirstPersonControls` has a new interaction model and improved mobile support.”

> “If you manually define pixel storage values over the raw WebGL 2 rendering context, use `renderer.state.pixelStorei()` now.”

Sprawdzić obrót background/environment, jeżeli Seedvale go ustawia; kontrole gracza, szczególnie mobile; oraz wszystkie bezpośrednie operacje na raw WebGL2 pixel storage.

### r184 → r185 — WebGPU / postprocessing / loaders

> “`WebGPURenderer` has changed how premultiplied alpha is implemented.”

> “The `clearColor` and `clearAlpha` properties of `SSAAPassNode` have been removed.”

> “`SVGLoader.createShapes()` has been deprecated. Use `shapePaths.toShapes()` instead.”

> “`AnamorphicNode` has been removed. Use `BloomNode`...”

> “`DRACOLoader.setDecoderConfig()` has been deprecated.”

Seedvale korzysta z WebGL2, więc WebGPU-specific zmiany nie powinny wymagać migracji, ale trzeba potwierdzić to w kodzie. Pozostałe API sprawdzić tylko jeśli występują.

## Plan implementacji

1. Ustalić dokładną obecną wersję `three` oraz powiązane wersje `@types/three` / loaderów, jeśli są używane.
2. Przeszukać repo pod kątem wszystkich API wymienionych w Migration Guide r180→r185.
3. Zaktualizować `three` do `0.185.x` oraz lockfile.
4. Nanieść tylko migracje rzeczywiście potrzebne Seedvale:
   - `PCFSoftShadowMap` → `PCFShadowMap`;
   - `Clock` → `Timer`, jeśli występuje;
   - pozostałe zmiany/deprecations/usunięcia wyłącznie dla używanych API.
5. Nie wykonywać niezwiązanych refaktorów ani zmian architektury renderingu.
6. Uruchomić TypeScript, lint, build i testy.
7. Naprawić ewentualne błędy/deprecation warnings wynikające bezpośrednio z upgrade'u.

## Weryfikacja techniczna

- `npx tsc --noEmit`
- `npm run lint`
- `npm run build`
- `npm run test`
- sprawdzić brak nowych błędów/deprecation warnings związanych z Three.js
- potwierdzić, że aplikacja nadal inicjalizuje WebGL2 renderer

## Weryfikacja wizualna — obowiązkowa

Przed upgrade'em, jeśli jest to możliwe, zachować screenshoty/reference frames tych samych scen. Po upgrade porównać:

1. **Terrain** — kolor, brightness, shading, slope transitions.
2. **Grass / foliage** — jasność, normal maps, wind, cienie; szczególnie sprawdzić wcześniejsze okresowe rozjaśnianie trawy.
3. **Trees / rocks / props** — roughness, specular response, ambient/environment lighting.
4. **Water** — reflections, brightness, transparency i environment reflection.
5. **Sky / sun / day-night** — jeżeli używane, sprawdzić cały cykl dnia.
6. **Shadows** — teren, drzewa, NPC, zwierzęta, props, campfires.
7. **Fog / weather** — clear, rain, snow, wet ground/puddles/snow cover.
8. **Settlements** — budynki, fires, roads, vegetation i landmarki.
9. **Lighting at night** — pochodnie, ogniska, światła osad.
10. **Mobile** — brak black-screen/flickering; szczególnie z foliage wind włączonym.
11. **Streaming** — podczas przemieszczania się przez chunk boundaries nie pojawiają się nowe artefakty wizualne.

## Performance / benchmark

Upgrade nie jest traktowany jako oczekiwany fix dla obecnego streamingu hitch. Po zachowaniu baseline wykonać ten sam benchmark `stream` i porównać:

- avg FPS
- p1 FPS
- avg frame time
- p95 frame time
- max frame time
- liczbę / długość największych hitchy
- pamięć / GC, jeśli benchmark ją raportuje

Jeżeli wynik zmieni się istotnie, oddzielić wpływ Three.js upgrade'u od pozostałych zmian w repo.
