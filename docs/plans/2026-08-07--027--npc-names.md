## Cel

Każdy NPC ma losowo generowane imię, które jest widoczne w:
- napisu nad głową (label NPC),
- dialogach reprezentacyjnych (przedstawianie się),
- future: quest log, notes, inne UI.

Brak roli/traits/personality traits — to odseparowana warstwa od [npc-character-depth.md](./2026-08-07--022--npc-character-depth.md) (role/Big Five/traits).

Rozszerzenie zakresu (patrz [Nazwy wiosek/osad](#nazwy-wiosekosad) niżej): każda wioska generowana przez [multi-settlements](./2026-08-07--025--multi-settlements.md) dostaje losową, seedowaną nazwę. Nazwa wioski:
- pojawia się przy NPC na liście dialogu / villagers screen (np. "Marek Kowalski — Dolina Wron"), żeby rozróżnić mieszkańców różnych osad,
- pojawia się na minimapie ([plans/2026-08-07--029--minimap.md](./2026-08-07--029--minimap.md)) jako label przy pinie osady — bez tego gracz łatwo się gubi między kilkoma wioskami, bo wszystkie wyglądają identycznie na mapie.

## Model danych

```ts
// Nowy typ w src/ai/characters.ts lub src/shared/
NPCName {
  firstName: string;
  lastName?: string;
  nickname?: string;
}

// Display name (precedens):
// 1. firstName + lastName (jeśli lastName istnieje)
// 2. firstName + nickname (jeśli nickname istnieje, lastName nie)
// 3. firstName + role (fallback, przy braku lastName/nickname)

displayName(): string {
  if (this.lastName) return `${this.firstName} ${this.lastName}`;
  if (this.nickname) return `${this.firstName} (${this.nickname})`;
  return `${this.firstName} z Osady`; // fallback z rolą: np. "Marek Drwal"
}
```

Nazwa generowana **raz** podczas tworzenia NPC (`createNpc.ts` lub istniejący seed-based NPC generator).

## Nazwy wiosek/osad

**Status:** `verification needed` — zaimplementowane w working tree (`src/shared/SettlementName.ts`, `src/settlement/settlementTerrain.ts`, wpięcie w `settlementGenerator.ts`/`SettlementsManager.ts`/`createSettlement.ts`, label na minimapie, badge w ekranie Mieszkańcy przy >1 wiosce), niezacommitowane, wymaga wizualnej weryfikacji w przeglądarce (nazwy w villagers screen, label na minimapie, korelacja z terenem dla kilku ziaren).

Reużywa generator imion (ten sam mechanizm: seedowane listy słów, deterministyczne per `(worldSeed, settlementIndex)`) — inna lista słów, inny wzorzec składania.

### Model danych

```ts
// src/shared/SettlementName.ts (albo obok NPCName.ts, jeśli wspólny plik ma sens)
SettlementName {
  name: string; // gotowa, złożona nazwa — nie trzeba osobnego displayName()
}
```

Nazwa generowana **raz** w `settlementGenerator.ts` przy tworzeniu wpisu wioski (razem z `site`/pozycją), zapisywana w `SaveData` (persystencja) tak samo jak reszta stanu osady — inaczej nazwa zmieni się po reloadzie.

### Wzorzec generowania

Polska konwencja nazw miejscowości — złożenie z dwóch list, **skorelowane z terenem najbliższym siedlisku wioski** (nie czysto losowe) — nazwa ma sugerować, gdzie leży wioska (bagno, ocean/wybrzeże, las, góry, pustynia), tak jak realne nazwy miejscowości (np. "Zalesie", "Podgórze", "Nadmorska").

**Klasyfikacja terenu wokół siedliska:** w miejscu `SettlementSite` (`findSettlementSite.ts`) próbkować istniejące osie makro-terenu — te same, których już używa `terrain/chunkHeightmap.ts` i `terrain/biomeRegions.ts` do renderu:
- `continentalness` (`sampleContinentalnessAt`) — nisko → **ocean/wybrzeże**,
- `mountainRidge` (`sampleMountainRidgeAt`) — wysoko → **góry**,
- `biomeWeightsAt(moistureRegion, altitude01, region)` — dominująca waga `swamp`/`desert`/`forest` → **bagno / pustynia / las** (las jest domyślny/remainder, tak jak w renderze biomów).

Wynik: jedna etykieta terenu per wioska (`'ocean' | 'mountain' | 'swamp' | 'desert' | 'forest'`), wybrana jako max z powyższych sygnałów w promieniu siedliska (próbka w kilku punktach wokół `site`, nie tylko w centrum — wioska rzadko stoi dokładnie na szczycie klasyfikowanego regionu).

| Typ terenu | rdzeń/przymiotnik | rzeczownik/topografia |
|-----|-----|-----|
| forest (domyślny) | Lipowa, Zielona, Sośni(k/ca), Brzozow(y/a), Cicha | Dolina, Grąd, Osada, Polana, Chatki |
| ocean/wybrzeże | Nadmorska, Słona, Rybacka, Piaszczysta | Brzeg, Zatoka, Przystań, Wybrzeże, Ostrów |
| mountain | Skalista, Wysoka, Kamien(na/ny), Górska | Wzgórze, Przełęcz, Turnia, Podgórze |
| swamp | Mokra, Bagienna, Trzcinowa, Głęboka | Ług, Rozlewisko, Moczary, Trzęsawa |
| desert | Sucha, Piaskowa, Wypalona, Jałowa | Wydma, Pustkowie, Ostoja, Karawana |

Wzorce składania (losowy wybór wzorca per wioska, w obrębie właściwej listy terenu):
- `{przymiotnik} {rzeczownik}` — np. "Bagienna Trzęsawa" (swamp), "Skalista Turnia" (mountain)
- `{rzeczownik} {przymiotnik}` — np. "Przystań Rybacka" (ocean), "Osada Stara" (forest)
- sam rzeczownik + sufiks `-ów`/`-owo`/`-ice` (uproszczony, bez pełnej polskiej fleksji) — np. "Lipowo" (forest), "Wydmowo" (desert)

Uwaga: pełna polska fleksja (uzgadnianie rodzaju/przypadka rdzenia i sufiksu) to złożony temat — v1 celuje w listę gotowych, już odmienionych fragmentów per kategoria terenu, zamiast programowej fleksji, żeby uniknąć gramatycznych potworków.

## Zaimplementowane: kulturowe pule imion

**Status:** `verification needed` — zaimplementowane w working tree, niezacommitowane w chwili pisania tej notatki, wymaga wizualnej weryfikacji w przeglądarce (etykiety nad NPC, ekran Mieszkańcy) na kilku ziarnach.

Zamiast pełnego `NPCName`/`displayName()` (firstName/lastName/nickname) z sekcji "Model danych" powyżej, na życzenie użytkownika zaimplementowano prostszy, ale bardziej zróżnicowany mechanizm: **kulturowe pule imion per wioska**.

- `src/ai/nameCultures.ts` — `NameCulture = 'polish' | 'spanish' | 'english'`, pule imion męskich/żeńskich per kultura (`NAME_POOLS`), `pickNameCulture(settlementSeed)` (losuje dominującą kulturę wioski), `generateNpcName(settlementSeed, npcIndex, gender, dominantCulture)` (90% szans imię z dominującej puli, 10% szans imię z innej, losowo wybranej kultury).
- `src/settlement/settlementGenerator.ts` — `SettlementDef` ma teraz `nameCulture: NameCulture` i `npcNames: readonly string[]` (jedno imię per slot NPC, wygenerowane raz przy tworzeniu wpisu wioski — deterministyczne, nie wymaga osobnego zapisu w save, tak jak `name`/`terrain`).
- `src/ai/NpcAgent.ts` — `NpcAgent.create()`/konstruktor przyjmują opcjonalny `nameOverride?: string`; gdy podany, zastępuje `character.name` z `characterForIndex(treeIndex)` (rola/osobowość/traits/płeć nadal pochodzą z `characterForIndex` bez zmian).
- `src/settlement/createSettlement.ts` — przekazuje `def.npcNames[i]` jako `nameOverride`.

**Ważne ograniczenie (świadoma decyzja projektowa): wioska domowa (`isHome`) NIE dostaje losowych imion kulturowych.** Jej NPC-e zachowują dokładnie oryginalne imiona ze stałej puli `CHARACTERS` w `src/ai/characters.ts` (Anna, Piotr, Kasia, Marek, Ola, Tomek, Zofia, Jacek — przypisywane deterministycznie po indeksie `characterForIndex(treeIndex)`, bez zmian). Powód: `src/quests/quests.ts` twardo koduje `giverName: 'Anna'` / `'Kasia'` / `'Marek'` / `'Piotr'` — `QuestManager.onInteract(npcName)` dopasowuje questy po dokładnym stringu imienia NPC. Losowanie imion w wiosce domowej rozjechałoby te stringi i po cichu zepsuło jedyny istniejący system questów w grze (questy między wioskami są poza zakresem — patrz `multi-settlements.md`). Inne (nie-domowe) wioski nie mają questów, więc dostają pełną losowość kulturową bez ryzyka.

`nameCulture`/`npcNames` są liczone dla każdej wioski (także domowej, dla spójności typu `SettlementDef`), ale `createSettlement.ts` po prostu ignoruje `npcNames` dla `isHome` (przekazuje `undefined` jako `nameOverride`, więc `NpcAgent` używa `character.name` jak dawniej).

## Alternatiwy rozważane i odrzucone

| Alternatywa | Dlaczego nie |
|-------------|-------------|
| Personalne systemy imion per każdą rolę (np. Drwal has "Leśnik" nickname automatycznie) | Skomplikuje generator, duplikuje logikę role assignment; imiona powinny być niezależne od roli w v1 |
| Pełna baza danych imion w osobnym JSON / `public/assets/` | Overkill na start; lista w kodzie (`chararcters.ts`) wystarczy |
| Generowanie imion ad-hoc (bez seeda) | Uniemożliwia save/persistence; breakuje przy reload (`npcIndex` musi być deterministyczny) |
| Big Five personality → nazwa (np. extravert = bołtacz) | Już pokryto w `npc-character-depth.md`, nie duplikować |
