# Plan: NPC Names v1 (Simple Identity)

**Status:** `planned`  
**Created:** 2026-08-07  
**Priority:** niski — czysto kosmetyczne, zero wpływu na mechanikę gry; zero konfliktu z istniejącymi systemami (`CharacterDef`, `Personality`, `HealthState`); może być wdrożone niezależnie lub czekać na wizualny/UI overhaul

## Cel

Każdy NPC ma losowo generowane imię, które jest widoczne w:
- napisu nad głową (label NPC),
- dialogach reprezentacyjnych (przedstawianie się),
- future: quest log, notes, inne UI.

Brak roli/traits/personality traits — to odseparowana warstwa od [npc-character-depth.md](./2026-08-07--022--npc-character-depth.md) (role/Big Five/traits).

---

## Model danych

```ts
// Nowy typ w src/ai/characters.ts lub src/shared/
NPCName {
  firstName: string;
  lastName?: string;
  nickname?: string;
}

// Display name (precedens):
// 1. firstName + lastName (jeśli lastName istnieje)
// 2. firstName + nickname (jeśli nickname istnieje, lastName nie)
// 3. firstName + role (fallback, przy braku lastName/nickname)

displayName(): string {
  if (this.lastName) return `${this.firstName} ${this.lastName}`;
  if (this.nickname) return `${this.firstName} (${this.nickname})`;
  return `${this.firstName} z Osady`; // fallback z rolą: np. "Marek Drwal"
}
```

Nazwa generowana **raz** podczas tworzenia NPC (`createNpc.ts` lub istniejący seed-based NPC generator).

## Dane imion

Listy losowe (polska konwencja):

| Typ | Przykłady |
|-----|-----------|
| firstName (♂) | Jan, Marek, Kuba, Jakub, Piotr, Andrzej, Tomasz, Stanisław, Paweł, Sławomir |
| firstName (♀) | Anna, Maria, Zofia, Krystyna, Barbara, Katarzyna, Agnieszka, Grażyna, Helena, Danuta |
| lastName | Kowalski/Kowalska, Nowak, Wiśniewski/Wis­niejsza, Zielinski/Zielinska, Szymanski/Szymańska, Lewandowski/Lewandowska |
| nickname (folk/diminutive) | Zielarka, Drwal, Rybaczka, Leśnik, Młynarz, Kowol, Gornik |

Losowy dla każdego NPC:
- Wybierz firstName z listy odpowiedniej płci.
- 60% szans: wybierz lastName.
- 30% szans: wybierz nickname.
- 10% szans: bez lastName/nickname (display "firstName z Osady").

## Dialog

Rozszerzenie istniejącego systemu dialogu (`src/ai/dialogue.ts`):

Nowe linie (`BANK`):

```ts
// Pytanie gracza: "Jak masz na imię?"
BANK = {
  greetingNameRequest: [
    { personality: 'curious', text: `Mam na imię ${npc.displayName}.` },
    { personality: 'cheerful', text: `Wołają na mnie ${npc.displayName}!` },
    { personality: 'gruff', text: `${npc.displayName}. Czego chcesz?` },
    { personality: 'quiet', text: `...${npc.displayName}.` },
  ],
}
```

Interakcja:
1. Gracz patrzy na NPC i naciska `[E]` (istniejące `Interactable` system).
2. NPC odpowiada dialogiem z osobowością (losowe z `BANK[topic][personality]`).
3. displayName jest interpolowany w tekście (`${npc.displayName}`).

## Kierunek

**Faza 1 (MVP, teraz):**
- Generator imion z seedem
- displayName w labelu nad NPC
- Zakulisowe — kod bez widocznego zaburzenia

**Faza 2 (gdy będzie UI dla dialogów):**
- Linie "Jak masz na imię?" w `BANK`
- Interpolacja `${displayName}` w dialogach

**Faza 3+ (future):**
- Quest log / notes UI — wyświetlanie imion i/lub relacji per NPC
- Dynamiczne imiona (zmiana after quest/event — niche feature, `Nice to have`)

## Alternatiwy rozważane i odrzucone

| Alternatywa | Dlaczego nie |
|-------------|-------------|
| Personalne systemy imion per każdą rolę (np. Drwal has "Leśnik" nickname automatycznie) | Skomplikuje generator, duplikuje logikę role assignment; imiona powinny być niezależne od roli w v1 |
| Pełna baza danych imion w osobnym JSON / `public/assets/` | Overkill na start; lista w kodzie (`chararcters.ts`) wystarczy |
| Generowanie imion ad-hoc (bez seeda) | Uniemożliwia save/persistence; breakuje przy reload (`npcIndex` musi być deterministyczny) |
| Big Five personality → nazwa (np. extravert = bołtacz) | Już pokryto w `npc-character-depth.md`, nie duplikować |
