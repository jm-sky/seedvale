## A. Executive summary

**Werdykt:** warstwa Vue (Fazy 0–4) jest spójna architektonicznie (jeden store + facades), ale UX gracza jest wciąż „warstwą narzędziową”: mieszanka PL/EN, debug w HUD, stałe listy akcji z feedbackiem w guziku, a na landscape telefonu chrome się gryzie.

**Co działa dobrze**
- Jednolity ciemny panel (`bg-panel` / `text-ink`) na pauzie, inventory, questach, world config.
- Escape stack / `useOverlayScreen` — sensowna modalność.
- Toast już istnieje i jest używany w gameplay (`ToastStack`, issue 012).
- Touch targets pauzy / E / Zap (≥44–68px) są OK; joystick vanilla to świadoma decyzja.
- Minimapa + FAB nie blokują centrum ekranu na desktopie.

**Najważniejsze problemy**
1. **High** — landscape A55: hint `Joystick = ruch` nadal widoczny (`max-[700px]` vs ~832 CSS px); Quick Actions nachodzi na pauzę / minimapę / paski.
2. **High** — status błędów w guzikach Quick Actions / Pauza→Akcje zamiast toastu; zawsze pełna lista akcji ognia.
3. **High** — mix PL/EN na ścieżce krytycznej (start, pauza, settings).
4. **Medium** — FPS + długa ściana skrótów w HUD wyglądają jak debug.
5. **Medium** — shadcn zainicjowany, nieużyty; light `:root` vs dark `@theme`; martwy CSS po migracji Vue w `index.html`.

## C. Problems

### C1. Hint joystick na landscape A55
- **Severity:** High  
- **Obszar:** HUD / mobile  
- **Problem:** `HudScreen` chowa hint tylko przy `max-[700px]:hidden`. A55 landscape ≈ **832×384** CSS px → hint zostaje.  
- **Dlaczego:** na szerokim-niskim ekranie zajmuje rzadką przestrzeń i dubluje Notatki / stopkę pauzy.  
- **Rekomendacja:** ukryć touch-hint zawsze gdy `isTouchDevice()` (albo breakpoint na `max-height` / `(pointer: coarse)`); zostawić w Notatkach.  
- **Plik:** `HudScreen.vue`, `store.ts` (`HUD_HINT_TOUCH`)  
- **Evidence:** `_temp/ui-review/seedvale-ui-mobile(1).png`; browser 832×384 z touch: `hintVisible: true`

### C2. Kolizja layoutu touch: Pause + Minimap + Quick Actions
- **Severity:** High  
- **Obszar:** mobile chrome  
- **Problem:** trzy niezależne `fixed` kontenery (`TouchChrome` pauza, `MinimapScreen` `top: max(68px,…)`, panel QA `bottom: max(190px,…)`). Na wysokości 384px panel QA startuje wysoko i nachodzi na prawą krawędź (pauza, `+` minimapy, CSS2D HP).  
- **Dlaczego:** brak wspólnego layoutu prawej kolumny; fixed offsets nie skalują się z `dvh`.  
- **Rekomendacja:** jeden flex column right-edge (pause → minimap → spacer → QA panel powyżej E/Zap); QA jako sheet od dołu na niskim `dvh`.  
- **Pliki:** `TouchChrome.vue`, `MinimapScreen.vue`, `QuickActionsScreen.vue`  
- **Evidence:** `seedvale-ui-mobile(1).png`; DOM A55: QA `y≈38` przy pause `y=16` / minimap `y=68`

### C3. Status błędu w guziku zamiast toastu
- **Severity:** High  
- **Obszar:** Quick Actions / Pauza→Akcje  
- **Problem:** `'Brakuje surowców'`, `'Brakuje kamieni'` itd. renderowane w `QuickActionsButton` / inline w labelu pauzy (timeout 1.5s). Toast już jest.  
- **Dlaczego:** tekst nie mieści się w wąskim guziku; niespójny feedback vs pickup/error toast.  
- **Rekomendacja:** `showToast(..., 'error'|'info')`; guzik bez `:status` (ew. krótki disabled reason).  
- **Pliki:** `QuickActionsScreen.vue`, `PauseMenuEntriesActions.vue`, `ToastStack.vue`  
- **Evidence:** snapshot „Zbuduj palenisko … **Brakuje kamieni**”; mobile start shot z kosztami w guzikach  
- **Powiązane:** issue [012](../issues/2026-08-10--012--toast-notifications-for-quick-feedback.md)

### C4. Pełna lista akcji zamiast dostępnych
- **Severity:** High  
- **Obszar:** Quick Actions / Akcje  
- **Problem:** zawsze 4 akcje ognia; shovel/tent/town częściowo filtrowane (`hasShovel`, `hasTent`, `nearTown`).  
- **Dlaczego:** szum, fałszywe affordances, duplikacja ścieżek.  
- **Rekomendacja:** wspólny katalog akcji + predicaty `available`; ukryj niedostępne (opcjonalnie sekcja „Niedostępne” później).  
- **Pliki:** `QuickActionsScreen.vue`, `PauseMenuEntriesActions.vue`, `userActions`

### C5. Mix PL / EN na ścieżce gracza
- **Severity:** High  
- **Obszar:** start / pauza / settings  
- **Problem:**  
  - Start: `Zapisano` + `Continue` / `New Game`  
  - Pauza: `Resume` / `Save` / `New Game` / `Seed` obok `Zadania` / `Ekwipunek` / `Akcje`  
  - Settings: `Character` / `Name` / `Toggle debug panel`  
  - Save status: `'Saved'`  
- **Dlaczego:** wygląda na niedokończoną lokalizację; obniża zaufanie do UI.  
- **Rekomendacja:** PL jako domyślny copy (Kontynuuj, Wznów, Zapisz, Nowa gra, Zapisano, Postać, Imię…).  
- **Pliki:** `createStartScreen.ts`, `PauseMenuEntriesMain.vue`, `PauseMenuEntriesSettings.vue`  
- **Evidence:** `desktop-start.png`, `desktop-pause.png`

### C6. HUD jak debug chrome
- **Severity:** Medium  
- **Obszar:** HUD  
- **Problem:** FPS w głównej linii statusu; długa ściana skrótów zawsze widoczna na desktopie.  
- **Dlaczego:** konkuruje ze światem 3D; wygląda jak warstwa deweloperska.  
- **Rekomendacja:** FPS tylko przy debug/lil-gui lub ustawieniu; hint skrócić / przenieść do Notatek / pierwszego uruchomienia.  
- **Plik:** `HudScreen.vue`, źródła `setHudFps`  
- **Evidence:** `desktop-hud.png`

### C7. Inventory: gęstość + małe targety
- **Severity:** Medium  
- **Obszar:** ekwipunek  
- **Problem:** karty z wagą + kategoria + `Weź`/`Wyrzuć`; zmierzone **Weź ≈ 44×26 px** (<44px wysokości).  
- **Dlaczego:** na touch trudne w trafienie; desktop OK, mobile słabo.  
- **Rekomendacja:** min. wysokość 44px na touch; ikony itemów (issue 005 / assety); uprościć wagę w details.  
- **Pliki:** `InventoryScreenItemList.vue`, `ItemsScreenItemButton.vue`  
- **Evidence:** `seedvale-ui-desktop(2).png`; pomiar browser

### C8. Duplikacja Quick Actions ↔ Pauza→Akcje
- **Severity:** Medium  
- **Obszar:** Vue architecture  
- **Problem:** te same 4 akcje + rozjechane komunikaty statusów (np. `'Brakuje surowców'` vs `'Brakuje kamieni'` / `'Brakuje surowców / krzesiwa'`).  
- **Rekomendacja:** jeden moduł `playerActions` (label, cost, run, availability) konsumowany przez oba UI.  
- **Pliki:** j.w.

### C9. shadcn-vue zainicjowany, nieużyty + konflikt tokenów
- **Severity:** Medium  
- **Obszar:** design system  
- **Problem:** `components.json` + `cn()` + light `:root` (`--background: oklch(1 0 0)`) na `body`; gry używa `--color-panel` / `--color-ink`. Brak `components/ui/*`.  
- **Rekomendacja:** dark tokens jako źródło prawdy; dodać tylko Button/Dialog/Input gdy potrzeba paneli; nie migrować HUD/chrome.  
- **Plik:** `tailwind.css`

### C10. Martwy CSS po migracji Vue
- **Severity:** Low  
- **Obszar:** `index.html`  
- **Problem:** `.seedvale-quest-log*`, `.seedvale-inventory*`, `.seedvale-hud*`, `.seedvale-npc-dialog*`, części `.seedvale-pause__*` nieużywane przez Vue (start screen nadal używa podzbioru pause).  
- **Rekomendacja:** wyczyścić martwe reguły; zachować touch / loading / npc-label / start / rotate-hint.

### C11. lil-gui widoczne dla gracza (desktop)
- **Severity:** Medium (dev/prod zależnie)  
- **Obszar:** debug  
- **Problem:** panel „Seedvale” / foldery EN widoczne bez `?debug=1`.  
- **Rekomendacja:** domyślnie ukryty; odsłaniać z Ustawienia → „Panel debug” (już jest toggle) lub `?debug=1`.  
- **Plik:** `createDebugGui.ts`

### C12. Contrasty HUD vs jasne niebo / fog
- **Severity:** Low–Medium  
- **Obszar:** a11y  
- **Problem:** biały tekst HUD bywa słaby na foggy sky mimo `text-shadow`.  
- **Rekomendacja:** lekki scrim / mocniejszy shadow na bloku HUD (nie na całym świecie).

## D. Design system

Bazować na istniejących tokenach gry (nie na light shadcn `:root`):

| Token | Rola |
|-------|------|
| `--color-panel` | tło paneli / modal |
| `--color-panel-backdrop` | dim świata |
| `--color-ink` | tekst na panelach i HUD |
| `--color-primary` | akcent (held tool, linki) |
| `--radius` | 10px panele; 8px kontrolki |

**Typografia:** jeden sans (obecnie Inter z Google Fonts — OK na start; później rozważyć font bardziej „światowy”, nie adminowy). Hierarchia: czas HUD 22–28px → tytuł panelu ~18px → body 14px → meta 11–13px.

**Przyciski:** 3 warianty — primary (Wznów), ghost (lista), danger (Nowa gra). Min. wysokość 44px na touch.

**Panele:** `bg-panel` + blur backdrop; max-width `md` (pauza) / `3xl` (inventory).

**Toast:** top-center, warianty info / pickup / error (już są).

**HUD:** minimalny (czas, faza, waga, held); bez FPS; bez długiego hintu na touch.

**Ikony:** Lucide tylko w chrome (Menu, Zap, ±); itemy — później sprite/ikona z katalogu.

## E. Responsive strategy

1. **Desktop (≥900px):** mysz + skróty; FAB QA bottom-right; minimapa bottom-left; pauza wycentrowana.  
2. **Touch / coarse:** TouchChrome + joystick; ukryć desktop hint; Notatki = kanon sterowania.  
3. **Landscape phone (szerokość >700, wysokość <500):** traktować jak touch-compact — wspólna prawa kolumna; QA jako bottom sheet; nie polegać wyłącznie na `max-[700px]`.  
4. **Safe area:** już częściowo (`env(safe-area-inset-*)`) — utrzymać przy refaktorze layoutu.  
5. **Modale:** `max-h-[calc(100dvh-32px)]` + scroll — OK; na landscape pilnować, by nie kolidowały z E/Zap.

## F. Vue / CSS architecture

**Docelowo**
- Zostawić `store` + facades — nie drugi system.
- Wyciągnąć `UiPanel`, `UiButton` (thin wrappers Tailwind / później shadcn Button).
- Jeden `playerQuickActions.ts` (definicje + availability) → QuickActions + Pause Akcje.
- Feedback błędów → tylko `showToast`.
- shadcn: dodać primitives **gdy** budujesz formularze (WorldConfig, Character); HUD zostaje custom.
- Dark tokens w `@theme`; light shadcn `:root` albo usunąć, albo nadpisać pod dark game shell.
- Wyczyścić martwy CSS w `index.html`; joystick/CSS2D/start zostają CSS.

**Nie robić**
- Pełnej migracji do shadcn Dialog dla każdego ekranu naraz.
- Przenosin joysticka do Vue w tej fazie.
